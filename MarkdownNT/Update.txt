【版本号规则】
--------------------------------------------------------

  * 修复编译错误时，如果错误数量大于 5 个，编辑器版本号升级最小版本
    （例如 1.2.12 → 1.2.13），并在更新日志中标出：
    “修复了一些代码错误”
  * 编译警告只进行修复，不更新编辑器版本号，也不要求新增版本日志
  * 少于或等于 5 个编译错误时，按照实际改动范围决定是否更新版本号

【2026-08-29】MarkdownNT.Core v1.1.4
--------------------------------------------------------

修复
  * 修复标准 Markdown 代码块未被识别的问题：
    - 现在支持 ```language 和 ``` / ~~~ 语法
    - 兼容原有的 >>> 代码块分隔符
  * 未指定语言的代码块默认按 text 处理，确保预览和导出行为一致
  * 代码块识别逻辑兼容标准 Markdown 与项目自定义语法

新增
  * 核心内核继续保留 PDF 导出能力：
    - 提供 PdfExporter.ExportToPdf(string) 返回 PDF 字节数组
    - 提供 PdfExporter.ExportToPdf(string, Stream) 直接写入输出流
    - 支持标题、段落、引用、列表、分隔线、代码块和基础表格
  * 核心库继续保持无 UI 设计，不依赖 Avalonia
  * PDF 导出自动嵌入系统中文字体，修复中文标题、正文、代码块及强调文本乱码
  * 标题、正文和强调文本统一使用同一中文字体文件
  * 代码块优先使用等宽中文字体，避免中文代码显示比例异常

注意
  * PDF 导出使用 PdfSharpCore 依赖
  * PDF 字体取决于运行环境；需要稳定显示中文时，应由使用者配置可用中文字体

【2026-08-28】编辑器与渲染重构
--------------------------------------------------------

新增
  * 新增 MarkdownParser 共享解析器（MarkdownParser.cs）：
    - 块级解析逻辑统一收口，实时预览与 HTML 导出共用同一套代码，
      不再各自维护一份
    - 支持表格结构化解析：表头 / 数据行 / 列对齐（:--- :---: ---:）
  * 表格改为真实渲染：
    - 预览：以 Grid 表格呈现，表头加粗带底色，单元格有边线，
      支持 :--- / :---: / ---: 三种列对齐
    - 导出：输出标准 <table><thead><tbody> 结构，样式与预览一致
  * 编辑器升级为 AvaloniaEdit TextEditor 控件：
    - 自带撤销/重做、光标移动、文本选择等编辑器能力
    - 保留自动换行与 Consolas 等宽字体
  * 代码高亮配色支持明暗主题：深色/浅色分别采用 VS Code 风格
    配色（关键字 #569CD6/#0000FF，字符串 #CE9178/#A31515，
    注释 #6A9955/#008000），深色模式下对比度更好

修复
  * 安全修复：HTML 导出未转义普通文本，笔记中的 < > & 会破坏
    输出结构（存在注入风险）。现在先转义 HTML 实体，再替换
    Markdown 语法
  * HTML 导出列表改为输出单个 <ul> 包裹连续列表项，原来每个
    列表项都输出一对 <ul><li>，属于无效 HTML
  * 列表项解析改用正则，正确支持 Tab 分隔（如 "-	内容"），
    不再依赖 IndexOf(' ') 切割
  * 自动保存与编辑器内容脱节：清空内容后自动保存不再跳过，
    空文本也会同步写入 autosave.mdnt
  * 特殊块（@meta/@audio/@speaker）导出为带样式的段落，
    样式表新增 .markdownnt-special 规则

优化
  * 实时预览增加 300ms 防抖：停止输入后才刷新预览，
    长文档打字不再卡顿
  * 新建/打开文件后立即刷新预览与字数统计
  * 清除全部可空性编译警告（0 警告 0 错误）

工程
  * 初始化 Git 仓库（main 分支），新增 .gitignore
    （排除 bin/、obj/、.vs/ 等构建产物）

已知限制
  * 代码块内无法输入仅含 ">>>" 的行（会被识别为结束符）
  * 行内斜体 *...* 在遇嵌套星号（如 *a * b*）时匹配范围
    可能不准确
